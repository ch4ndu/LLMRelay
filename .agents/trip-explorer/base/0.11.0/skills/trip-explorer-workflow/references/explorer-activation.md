# Deterministic Explorer Activation

Explorer reduces total context only when it replaces broad manager discovery.
Do not activate it merely because the work feels unfamiliar.

## Bounded scope census

Before launch, the manager reads the repository router and its one routed task
guide, runs at most four targeted searches, and opens at most six relevant
source files. Identify the production modules, source sets/platforms, owner
symbols, expected production edit set, and focused verification commands.

Launch one planning Explorer only when at least one condition holds:

1. Production edits span two or more build modules.
2. Production edits span two or more platform-specific source sets, or an
   `expect` declaration plus two or more `actual` implementations.
3. The requested behavior changes a public API, persistence/network/auth
   contract, DI/module/dependency binding, platform bridge, playback
   controller/backend ownership, or release/signing/distribution contract.
4. The request explicitly asks for repository-wide, entire-project,
   all-consumer, every-implementation, or whole-area audit coverage.
5. The expected non-mechanical production edit set exceeds eight files.
6. A structural ownership/refactoring change targets a production file over
   2,000 lines.
7. After the census, the manager still cannot name the production module,
   source set, owner symbol, edit boundary, and focused verification command.

A mechanical change applies one already-resolved transformation without
changing control flow, data flow, ownership, or behavior. Test-only modules do
not satisfy the multi-module trigger unless production behavior crosses them.
A shared/common source set alone is one source set. Preserving a sensitive
existing contract does not satisfy the contract-change trigger.

## Rescue activation

During implementation or review, allow one rescue Explorer only when:

1. the same verification gate still fails after two consecutive repair
   attempts;
2. a failure reveals an unplanned production module, source set, or platform
   implementation;
3. a production path outside the approved edit set appears and cannot be
   attributed safely;
4. two review roles cite conflicting current-source evidence for the same
   acceptance criterion; or
5. four additional targeted searches still cannot identify the owner of a
   newly discovered behavior.

One rescue is the default maximum. A second requires a concrete manager
justification and explicit user approval.

## Invocation and measurement

Give Explorer one bounded evidence question. Require only the fact the census
could not establish, current file/symbol evidence, its decision impact, and
remaining uncertainty. Do not request a restatement of the user request, plan,
full diff, logs, counts already in the ledger, or implementation narrative.
Target at most about 800 words; a no-material-delta response should stay under
about 150.

Record the exact trigger, elapsed time, prompt/result size or available token
counts, unique evidence, decision change, manager reads avoided, downstream
rereading, and accepted finding. Retain the role only while the triggering
uncertainty remains active.
